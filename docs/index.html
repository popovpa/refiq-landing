Вся базовая интеграция RefIQ сводится к двум действиям: сохранить rqcid после перехода пользователя и передать его обратно в RefIQ при возникновении конверсии.

  1. Сохранить rqcid пользователя.
  2. Передать rqcid в RefIQ при возникновении конверсии.

Быстрый старт

Два действия. Остальное RefIQ делает сам.

  1. 01

    Сохранить rqcid

    После перехода по партнёрской ссылке идентификатор клика попадает на сайт бизнеса. Его нужно сохранить до целевого действия.

  2. 02

    Отправить Postback

    Когда пользователь совершает Goal оффера, backend бизнеса передаёт rqcid в RefIQ server-to-server.

Шаг 1. Пользователь переходит по партнёрской ссылке

Пример tracking link:

text 
https://go.refiq.ru/ab31ca

Как работает переход

RefIQ Tracker обрабатывает короткий код ссылки и передаёт rqcid на сайт бизнеса.

RefIQ Tracker:

  1. Находит TrackingLink

    По short_code из URL.

  2. Определяет связанные сущности

    Offer, Partner, Campaign если она задана, Destination URL.

  3. Регистрирует Click

    Фиксирует переход по tracking link.

  4. Создаёт уникальный rqcid

    rqcid связывает конкретный клик с TrackingLink, Partner, Offer и другими данными атрибуции.

  5. Выполняет HTTP 302

    Редирект на сайт бизнеса с rqcid в query-параметре.

Запрос:

http 
GET https://go.refiq.ru/ab31ca

Ответ:

http 
HTTP/1.1 302 Found
Location: https://shop.example.com/product/123?rqcid=rq_8f92a71c

Сохранение rqcid

Бизнес должен сохранить rqcid, чтобы он не потерялся между переходом пользователя и целевым действием.

  1. URL ?rqcid=...
  2. frontend / backend
  3. cookie / localStorage / session
  4. идентификация пользователя
  5. customer_id ↔ rqcid
  6. server-side storage
  7. заказ / lead / другая конверсия

Cookie или localStorage — только технический механизм временного хранения.

После идентификации пользователя предпочтительно сохранять связь customer_id ↔ rqcid server-side. Это позволяет не зависеть только от cookie и browser storage.

JavaScript SDK

Рекомендуемый простой вариант подключения. SDK помогает сохранить attribution context на сайте. SCRIPT_ID создаётся в кабинете бизнеса при подключении JavaScript SDK.

html 
<script>
  (function (window) {
    var match = location.href.match(/[?&#]rqcid=([a-z0-9]{12})/);
    if (match) {
      document.cookie = "rqcid=" + match[1] + ";path=/;max-age=31536000;SameSite=Lax";
    }
    var queue = (window.RefIQ = window.RefIQ || []);
    queue.event = function (name, data) {
      queue.push(["event", name, data]);
    };
  })(window);
</script>
<script async src="https://refiq.ru/sdk.js" data-id="SCRIPT_ID"></script>
  • определяет rqcid из URL
  • сохраняет attribution context в cookie
  • позволяет получить текущий rqcid
  • отправляет события через RefIQ.event

Публичный API SDK использует термин rqcid:

javascript 
const rqcid = RefIQ.getRqcid();

fetch('/api/orders', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    product_id: 123,
    rqcid
  })
});

Postback не должен отправляться из браузера. Postback отправляет backend бизнеса server-to-server.

Интеграция без SDK

RefIQ SDK не обязателен. Бизнес может самостоятельно прочитать rqcid.

javascript 
const params = new URLSearchParams(window.location.search);
const rqcid = params.get('rqcid');

После этого бизнес самостоятельно отвечает за:

  • сохранение rqcid;
  • перенос rqcid между страницами;
  • связь с зарегистрированным пользователем;
  • сохранение rqcid вместе с заказом или лидом.
  1. GET /product/123?rqcid=rq_8f92a71c
  2. сохранить rqcid
  3. customer / order
  4. orders.rqcid = rq_8f92a71c

Не нужно самостоятельно определять Partner или Offer. RefIQ определяет их по rqcid.

Clickstream

События поведения пользователя. Это не Conversion.

Endpoint:

http 
POST https://events.refiq.ru/event

JS SDK может автоматически отправлять события поведения пользователя. Например: page_view, click, form_start, form_submit.

json 
{
  "event": "page_view",
  "rqcid": "rq_8f92a71c",
  "url": "https://shop.example.com/product/123",
  "referrer": "https://example.com/"
}
  1. JS SDK
  2. events.refiq.ru/event
  3. Clickstream

Clickstream-событие не создаёт финансовую Conversion. Для регистрации Conversion бизнес должен отправить Postback.

Postback

Server-to-server запрос от backend бизнеса в RefIQ о наступлении целевого действия.

Примеры Goal: покупка, оплаченный заказ, lead, регистрация, подписка или другое Goal оффера.

Endpoint:

http 
POST https://api.refiq.ru/postback

Формат

json 
{
  "rqcid": "rq_8f92a71c",
  "goal": "purchase",
  "amount": 14990.00,
  "currency": "RUB",
  "timestamp": "2026-08-16T10:30:00Z"
}
Поле Обязательное Описание
rqcid Да Идентификатор атрибутируемого клика
goal Да Целевое действие Offer
amount Зависит от Goal Сумма операции
currency При наличии amount Валюта операции
timestamp Да Время возникновения Conversion
signature Опционально Подпись запроса, если используется

Примеры

bash 
curl -X POST https://api.refiq.ru/postback \
  -H "Content-Type: application/json" \
  -d '{
    "rqcid": "rq_8f92a71c",
    "goal": "purchase",
    "amount": 14990.00,
    "currency": "RUB",
    "timestamp": "2026-08-16T10:30:00Z"
  }'
javascript 
await fetch('https://api.refiq.ru/postback', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    rqcid: 'rq_8f92a71c',
    goal: 'purchase',
    amount: 14990.00,
    currency: 'RUB',
    timestamp: '2026-08-16T10:30:00Z'
  })
});
python 
import requests

requests.post(
    'https://api.refiq.ru/postback',
    json={
        'rqcid': 'rq_8f92a71c',
        'goal': 'purchase',
        'amount': 14990.00,
        'currency': 'RUB',
        'timestamp': '2026-08-16T10:30:00Z',
    },
)

Как работает атрибуция

У каждого Offer есть Attribution Window — период, в течение которого Conversion может быть засчитана партнёру.

Attribution Window — бизнес-правило.

Cookie — только технический способ сохранения attribution context.

Для MVP используется правило: last eligible partner click within attribution window.

  1. Partner A → Click A
  2. Partner B → Click B
  3. Conversion

Если Click B допустим и находится внутри Attribution Window:

Conversion → Partner B

Проверка интеграции

Ручная проверка без sandbox-режима.

  1. 01

    Открыть Tracking Link

    Перейти по https://go.refiq.ru/{short_code}.

  2. 02

    Проверить Destination URL

    В адресе сайта бизнеса должен появиться rqcid.

  3. 03

    Проверить сохранение

    Сайт сохранил rqcid в cookie, storage или server-side.

  4. 04

    Отправить тестовый Postback

    Backend вызывает POST https://api.refiq.ru/postback с сохранённым rqcid.

  5. 05

    Проверить Conversion

    Конверсия появляется в кабинете RefIQ.
